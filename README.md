# Сисадминский обходной лист

Общий запуск и отдельные проверки кабинетов по логину и паролю или сессии Chromium (Timeweb Cloud). Цветной краткий отчёт, подробности по подпискам и устройствам, JSON для дальнейшей обработки. Ошибка одного сервиса не прерывает остальные проверки.

## Запуск

Нужны Python 3.12+ и `uv`.

```sh
uv sync --locked
# Только при первой настройке, если .env ещё нет:
cp -n .env.example .env
chmod 600 .env
# Заполнить логины и пароли в .env
uv run python -m checklist
```

```sh
uv run python -m checklist --service smartvhod --details
uv run python -m checklist --service hosting
uv run python -m checklist --service crm
uv run python -m checklist --service cloud
uv run python -m checklist --json
```

`.env` загружается из корня проекта, независимо от рабочего каталога. Переменные окружения имеют приоритет. Подстановка `${...}` отключена, пробелы в пароле сохраняются. Для другого файла: `--env-file /path/to/.env`.

Коды завершения: `0` — проверенные пункты в порядке; `1` — нужны внимание/пополнение или есть ограничения данных; `2` — ошибка входа, сети, формата или неполная проверка. `SKIP` явно обозначает отложенный сервис и сам по себе не меняет код завершения.

## Что проверяется

| Сервис | Проверки |
|---|---|
| Timeweb Hosting | Баланс, непрочитанные новости с заголовками, незакрытые системные баннеры |
| SmartVhod | Баланс, старые и новые ключи, Multi-VPN, сроки и автопродление, устройства, бюджет на 30 дней |
| CRM Aspro | Только наличие непрочитанных системных объявлений сервиса |
| Timeweb Cloud | Баланс, расход, запас средств, новости и баннеры, блокировка аккаунта, состояние серверов, CPU, RAM и заполненность каждого диска |

CRM не запрашивает ленты, счётчики или содержимое уведомлений по задачам, сделкам и сообщениям. Системные объявления проверяются через состояние раздела помощи, без открытия отдельных новостей и отметки прочтения.

Hosting показывает системные баннеры кабинета; маркетинговые подсказки и обращения в поддержку в эту проверку не входят. Заголовки новостей получаются из списка; запрос отметки прочтения не вызывается.

## Только чтение

Нет браузерных кликов и выполнения JavaScript страниц. Разрешены авторизация, обновление сессии Cloud и фиксированный список запросов чтения. Настройки, подписки, устройства и статусы прочтения не изменяются. Клиент блокирует остальные маршруты и методы. Запросы ограничены таймаутами. Сессии хранятся в памяти процесса, кроме обновляемой сессии Cloud, описанной ниже.

Внутренние HTTP-интерфейсы найдены в коде самих кабинетов и проверены реальным входом. Временные токены авторизации программа получает сама. При CAPTCHA/2FA обход сообщает об ошибке, автоматически их не обходит. При изменении формата данных выдаётся ошибка, отсутствующие данные не заменяются нулями.

Пароли, сессионные токены и полные HTTP-ответы в отчёт не выводятся. `.env`, локальная конфигурация, диагностические файлы и каталог `reports/` исключены из Git. Подробный отчёт содержит названия устройств — учитывайте это при его сохранении и пересылке.

## Timeweb Cloud

По умолчанию `TIMEWEB_CLOUD_AUTH=auto`: при наличии профиля `~/.config/chromium/Default` используется его сессия Cloud, иначе — `TIMEWEB_CLOUD_LOGIN` и `TIMEWEB_CLOUD_PASSWORD`. Можно явно выбрать `chromium` или `password`. Другой профиль задаётся через `TIMEWEB_CLOUD_CHROMIUM_PROFILE` (каталог `Default` или `Profile N`, не корень Chromium). Поддерживается Linux Chromium с шифрованием cookies `v10`; Keyring/v11, Windows и macOS этим адаптером cookies не поддерживаются.

Из базы Chromium в режиме чтения выбираются только `refresh_token`, `device_token` и `qrator_msid2` для точных доменов `timeweb.cloud` и `.timeweb.cloud`. Cloud заменяет refresh-cookie при обновлении сессии, поэтому новая версия сохраняется в `.state/cloud-*.json` с правами `600`; каталог исключён из Git. Профиль браузера не изменяется. Одновременные обновления защищены блокировкой. Использование сессии может потребовать повторного входа в самом Chromium. После нового входа в браузере обход подхватит новую cookie автоматически. При истёкшей сессии выдаётся ошибка с предложением войти заново; скрытого перехода к паролю нет. Повреждённый файл `.state/cloud-*.json` нужно удалить перед новым входом.

Запас средств берётся из `hours_left` Cloud; предупреждение появляется при остатке до 30 дней включительно. Это оценка при текущем расходе, без прогноза смены тарифов и состава услуг. Платёжные поля соответствуют [API Timeweb Cloud](https://github.com/timeweb-cloud/sdk-python/blob/main/docs/PaymentsApi.md). Новости проверяются только по счётчику, без открытия и отметки прочтения. Баннеры объединяются из двух версий интерфейса кабинета с удалением дублей по ID; локально скрытые в браузере баннеры также попадут в отчёт.

Для каждого облачного сервера проверяются состояние, CPU, RAM и ROM (занятое место на каждом диске). **Строго больше 50% — `WARN`; ровно 50% — `OK`.** Порог сравнивается до округления. CPU берётся из `system.cpu.util` в процентах; RAM — `used / total × 100`, без файлового кэша; ROM — `used / size × 100` отдельно для каждого диска, без усреднения между дисками или серверами.

Для CPU и RAM запрашивается последний час и выбирается самый свежий замер по времени, а не максимум за час. В отчёте указано время замера. Отсутствующие значения, замеры старше 30 минут и метрики с признаком неактуальности дают `WARN`, без подстановки нулей. Выключенный, заблокированный или переходящий в другое состояние сервер также даёт `WARN`. Ошибки сети и некорректные ответы дают `ERROR`; проверки остальных ресурсов и серверов продолжаются. Список серверов читается со всеми страницами.

Статистика занятого места на диске обновляется Cloud примерно раз в час; API списка дисков не сообщает время замера. RAM может отсутствовать, если сбор метрик на сервере недоступен — обход не устанавливает агенты и не меняет сетевые правила. Подробнее: [статистика ресурсов Timeweb Cloud](https://timeweb.cloud/docs/cloud-servers/manage-servers/resource-stats).

## Прогноз SmartVhod

Горизонт по умолчанию — следующие 30 дней, включая списания точно на границе. Для каждой существующей подписки берутся срок окончания и цена продления на 30 дней. Рассчитываются все продления внутри горизонта, первое списание, на которое не хватает текущего остатка, общая сумма пополнения и рекомендуемый срок внесения денег за 3 дня до нехватки.

Прогноз предполагает сохранение всех перечисленных подписок, включая подписки с ручным продлением. Для истёкшей подписки требуется немедленное продление; новый период считается от момента обхода. Проверяйте эти случаи отдельно: фактические правила восстановления могут отличаться.

Если действует акция, выводятся сумма по текущим ценам и отдельный резерв по обычным ценам. Рекомендация с запасом относится к окончанию текущей акции; будущие изменения тарифов предсказать нельзя. **Выбранный для прогноза период не подтверждает период фактического автосписания**: внутренний API его не сообщает. У Multi-VPN состояние автопродления не возвращается; это явно указано в отчёте. У старых ключей интерфейс не предоставляет список устройств: выводится предупреждение.

Настройки `.env`:

```dotenv
CHECKLIST_TIMEZONE=Europe/Moscow
SMARTVHOD_HORIZON_DAYS=30
SMARTVHOD_LEAD_DAYS=3
```

При необходимости скопируйте `config.example.json` в `config.local.json`. `renewal_days` задаёт период продления для прогноза, а `price_ids` позволяет выбрать тариф для конкретной подписки, например `{"key:123": 6, "multi:456": 11}`. Это только настройка расчёта, она не меняет тариф в кабинете. Если подходящих тарифов несколько или нужный не найден, расчёт помечается неполным.

## Проверки кода

```sh
uv run python -m pytest -q
uv run ruff check checklist tests
```

Тесты используют искусственные данные без обращений к кабинетам: расчёт денег и дат, ограничения запросов, отсутствие чтения пользовательских уведомлений CRM, изоляция ошибок и скрытие секретов.

Для запуска по расписанию можно использовать cron/systemd с абсолютным путём к `.venv/bin/python` и рабочим каталогом проекта. Планировщик автоматически не устанавливается.
